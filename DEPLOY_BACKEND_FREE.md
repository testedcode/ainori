# Deploy Backend for Free (Replace Railway)

Your frontend is on **Vercel**; the backend needs a host that can run the Go API 24/7 (or with cold starts). Below are **free options** and exact steps.

---

## Option 1: Render.com (recommended)

**Free tier:** 750 hours/month, service spins down after ~15 min inactivity (wakes in ~30–60 seconds on next request).

### Steps

1. **Sign up**  
   [render.com](https://render.com) → Sign up (GitHub is easiest).

2. **Create Web Service from repo**  
   - Dashboard → **New** → **Web Service**  
   - Connect **GitHub** and select `testedcode/ainori`  
   - Use the repo that contains `render.yaml` and the `backend` folder.

3. **Configure the service**  
   - **Root Directory:** `backend`  
   - **Runtime:** Go  
   - **Build Command:** `go build -o server .`  
   - **Start Command:** `./server`  
   - **Instance Type:** **Free**

4. **Environment variables** (Render → your service → **Environment**)  
   Add:

   | Key            | Value |
   |----------------|--------|
   | `DATABASE_URL` | Your Supabase (or other Postgres) URI, e.g. `postgresql://postgres:YOUR_PASSWORD@db.xxxx.supabase.co:5432/postgres` |
   | `JWT_SECRET`   | A long random string (e.g. from [randomkeygen.com](https://randomkeygen.com) – 256-bit) |

   Get Supabase URI: [Supabase](https://app.supabase.com) → your project → **Settings** → **Database** → **Connection string** → **URI**.

5. **Deploy**  
   Click **Create Web Service**. After the first deploy, note the URL, e.g.  
   `https://cpool-backend-xxxx.onrender.com`.

6. **Point Vercel at the new backend**  
   - [Vercel](https://vercel.com) → your project → **Settings** → **Environment Variables**  
   - Set `NEXT_PUBLIC_API_URL` = `https://cpool-backend-xxxx.onrender.com/api` (your Render URL + `/api`)  
   - **Redeploy** the frontend so the new value is used.

7. **Admin login**  
   Migrations run on startup and seed the admin user. Use:
   - **Email:** `admin@135`  
   - **Password:** `password`  

   If login still fails, insert the admin once in Supabase **SQL Editor**:

   ```sql
   INSERT INTO users (email, password_hash, name, role, city) VALUES 
     ('admin@135', '$2a$10$N9qo8uLOickgx2ZMRZoMyeIjZAgcfl7p92ldGxad68LJZdL17lhWy', 'Admin User', 'admin', 'Mumbai')
   ON CONFLICT (email) DO NOTHING;
   ```

## Option 2: Deploy with Blueprint (render.yaml)

If your repo has `render.yaml` in the **root**:

1. Render Dashboard → **New** → **Blueprint**  
2. Connect the same GitHub repo  
3. Render will read `render.yaml` and create the Go web service  
4. In the **Environment** tab for that service, set:
   - `DATABASE_URL` (your Supabase/Postgres URI)  
   - Optionally leave `JWT_SECRET` to be generated by Render (or set your own)

Then do **steps 6–7** above (Vercel `NEXT_PUBLIC_API_URL` and admin login).

---

## Option 3: Fly.io (alternative)

Fly gives a **$5/month credit**; small apps often stay within free usage.

1. **Install Fly CLI**  
   [fly.io/docs/hands-on/install-flyctl](https://fly.io/docs/hands-on/install-flyctl) (Windows: PowerShell one-liner).

2. **Auth**  
   ```bash
   fly auth signup
   # or fly auth login
   ```

3. **Deploy from backend folder**  
   ```bash
   cd backend
   fly launch
   ```  
   - Use existing app or create new one  
   - Don’t add a Postgres (we use Supabase)  
   - When asked, say no to deploying now if you want to set secrets first.

4. **Set secrets**  
   ```bash
   fly secrets set DATABASE_URL="postgresql://postgres:PASSWORD@db.xxxx.supabase.co:5432/postgres"
   fly secrets set JWT_SECRET="your-long-random-secret"
   ```

5. **Deploy**  
   ```bash
   fly deploy
   ```

6. **Get URL**  
   `fly status` or Dashboard → your app → URL, e.g. `https://cpool-backend.fly.dev`.

7. **Vercel**  
   Set `NEXT_PUBLIC_API_URL` = `https://cpool-backend.fly.dev/api` and redeploy. Use admin `admin@135` / `password` (and seed via SQL if needed, same as above).

---

## Summary

| Item | What to do |
|------|------------|
| **Backend host** | Use **Render** (or Fly.io) instead of Railway |
| **Database** | Keep using **Supabase** (free tier) – set `DATABASE_URL` on the backend |
| **Frontend** | Vercel: set `NEXT_PUBLIC_API_URL` to your new backend URL + `/api`, then redeploy |
| **Admin** | `admin@135` / `password`; if missing, run the SQL insert in Supabase once |

After this, the app can keep running with no Railway plan: Vercel (frontend) + Render or Fly (backend) + Supabase (DB), all with free tiers.
